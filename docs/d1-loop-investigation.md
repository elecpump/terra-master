# D1 游戏循环静态勘察

日期：2026-09-11。此文是同步推进实验的准备，不是同步支持结论；当前模组仍为 realtime。M0 长测进行期间，仅只读检查安装版程序集，没有修改运行中的游戏。

## 可重复的检查入口

```powershell
.\inspect_loop.ps1 -OutputPath evidence/loop-inspection-v043.json
```

脚本使用安装目录自带 Mono.Cecil，不依赖超前的参考源码分支、不安装 SDK。输出安装版 DLL 的 SHA-256、产品版本及指定方法的相关 IL 指令，见 [静态检查结果](../evidence/loop-inspection-v043.json)。方法或依赖不唯一时拒绝输出。

## 已确认的调用顺序

`Main.DoUpdate` 的 `CanPauseGame()` 判断位于 `UpdateWeather`、`PreUpdateEntities` 和 `DoUpdateInWorld` 之前；暂停路径调用 `DoUpdate_WhilePaused` 后返回。自动存档和部分界面/动画更新位于该判断之前，因此不能假定这一判断冻结了所有状态。

`DoUpdateInWorld` 中玩家、NPC、弹幕、掉落物、时间、世界更新位于 `PostUpdateEverything` 之前。当前桥接恰在该结束点发布快照。静态顺序提示可在一次完整更新结束时消耗步进预算，但不能只按 Player.SetControls 次数宣称整世界推进了相同帧数。

`Player.Update` 的 ResetControls 后存在独立焦点分支，失焦时跳过 SetControls。0.4.3 已为真实后台补充桥接控制；同步实验必须继续验证该路径，不能因已有整世界门控而删除它。

## 下一实验切片

候选方案是在有效 Training 模式下，用非阻塞的单帧许可参与暂停判断；保留原有手动暂停条件。网络线程只提交预算，游戏线程消费许可。禁止在游戏线程等待请求，也不能单纯设置 gamePaused 就认定同步成立。

先增加独立诊断快照，记录玩家、全部活跃 NPC/弹幕、时间/昼夜、天气及回合/实例标识；诊断内部真值不进入正式策略观测。采样必须在相同更新边界完成，不能用更晚 observe 代替完成帧。冻结时的外层 runtime 心跳继续可读，便于区分冻结和卡死。

预登记用例：无许可空等 1 秒，游戏状态不变而网络心跳继续；分别授予 1/6/15 帧，所有目标系统推进且计数一致；前后台切换不改变语义；手动暂停期间请求零帧超时；恢复后旧请求不执行；取消/退出世界/撤销训练 marker 后输入释放。无界面、加速和确定性仍各自需要证据。

首先审计暂停判断之前的世界准备、存档和动画更新是否影响上述正式状态。若关键游戏状态仍跨越冻结边界变化，或无法给出一致完成帧快照，该候选方案不能判通过。D1 保留原定两工程日时间盒；失败记录 unsupported 并继续实时路线，不延长为无限期研究。

自然世界的死亡可用于观察死后计时是否冻结，但不能成为首个导航训练场景。无自然刷怪、完整 reset 与合法死亡 transition 属后续场景切片，不能用无敌或删除死亡样本替代。
